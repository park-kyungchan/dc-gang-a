# Windows Desktop harness

Start with the [context and authority map](context-map.md), then use the dated project handoff for current phase and evidence.

Run `python -B harness/desktop_gate.py --profile core` from this project root or a clean managed worktree. It checks Python 3.12, the retired saved-session paths, the synthetic Main Sheet tests, the pinned backend map, the exact companion LMS reader source hashes, the VS Code-to-Desktop transition package, and the SPT checkout identity/dirty count. It reads no student record or credential value, makes no network request, and leaves the SPT checkout unchanged.

The command reports `local_workspace_gate=pass` only when every required check for the selected profile passes. `--profile live` additionally requires a project-local `.venv`, importable companion reader, and exact 22-package lock. Worktrees do not copy the ignored `.venv`, so do not install the 250 MiB optional live environment merely to run core tests. A changed SPT branch, HEAD, or dirty-path set fails either profile; dirty file contents are still not verified. App project association and live academy access are explicitly outside both profiles. The synthetic harness policy tests cover drift, missing, and unavailable required checks.

The `academy_auth` item reports only whether `GANGA_JSESSIONID` exists in this process environment. `configured` is not a validated login. The gate never invokes `LmsSession`, automatically discovers browser cookies, or calls the academy. The optional `academy_dayrecord_probe.py --live` performs one exact, source-reviewed 2026-09-21 all-groups DayRecord read only when the source lock matches and ephemeral authentication is present. `--live --prompt-auth` is an explicit alternative that accepts one session value through a hidden terminal prompt for that process only; never paste it into chat. The probe suppresses request logging and emits aggregate structure only. Its optional Python dependencies are declared in `requirements-live.txt` and pinned in `requirements-live.lock.txt`; a project-local `.venv` now imports the companion reader, and `pip check` passed. Browser and Computer Use remain UI tools, while workspace edits and local checks use file and shell tools.

Keep the historical `Runtime-Guide` transition package and remote/Snapshot manifests as immutable source evidence. Update this project's dated handoff when a phase changes. The Main Sheet and SPT are separate worktrees and authorities; this gate only checks their local state.

The Codex app recognizes this chat under the saved local Git project. A clean managed worktree was created from the curated baseline and contains no `config/`, `data/`, or ignored `.venv/`. The project has no app-generated project-root `.codex` local-environment file, so top-bar actions or automatic worktree setup scripts have not been configured. See the [local Git baseline record](git-baseline-plan.md). Do not hand-write an undocumented local-environment file or broaden sandbox/network permissions to make a test green.

If a top-bar action is useful, add it through Codex Settings > Local environments with label `Core Gate` and Windows command `python -B harness/desktop_gate.py --profile core`. The standard-library core needs no automatic worktree setup script. This is a copyable configuration value, not evidence that the app action has been installed.
