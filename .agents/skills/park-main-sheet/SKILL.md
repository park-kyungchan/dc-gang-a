## Build the working view

- Keep one visible teacher tab with date-first whole-class preparation, live task/waiting/next-task status, and closeout in that order. Keep selected-student detail available without hiding the whole class.
- Treat the Main tab as a projection over exact lesson/student identities, source facts, append-only teacher events, drafts, and verified effects. Keep unknown app joins visibly unknown.
- Bind a concept whiteboard test to the verified previous lesson occurrence's separate textbook assignments. Keep book possession and inspection states separate, support a waiting buffer task, and retain task cancellation reason. `workbench_v2/concept_scope.py` provides an I/O-free binding check.
- Select the prior **held** lesson from a complete schedule window; skip sessions verified cancelled for holidays. For the 2026-09-30 pilot, the teacher has already confirmed 2026-09-23 as 이루한's relevant prior held lesson because of the holiday gap. Do not ask for that date again. The exact LMS occurrence and book-edition bindings remain unverified; investigate those joins without downgrading the teacher's date decision.
- Before accepting a student's homework inspection as complete, compare the verified assigned-book set with each book's inspection state. If a book remains unresolved, ask the teacher about that exact book and distinguish student possession from teacher inspection; never turn a whole-student checkmark into all-book completion.
- For direct entry, use a fixed input area and an explicit `기록` action. Chat input uses the same idempotent event writer. Do not rely on `onEdit` for script/API writes or a drawing button on mobile.
- For weekly homework, show a date-scaled baseline at 14:00 and recompute a student/book proposal before class ends. Require verified calendar completeness, book edition/TOC, complete page audit and individual pace before suggesting a new-unit review interval. The conservative end reserves a slot per unfinished subunit; the page-share end is only a capacity ceiling, since page difficulty is unknown. Teacher approval is a separate event. Do not use time spent. Accuracy weighting waits for exact app grading joins and student-specific teacher interview. Keep question-level page audit in the backlog.
- Capture classroom question details as immutable raw teacher input against an exact student/lesson before normalization. Show every student's unresolved inputs in an anytime cleanup queue and prominently at 21:30-22:00 after class. Teacher-inspected page completion requires checked wrong-answer correction; app grading, the first correction pass, starred questions, and final inspection stay separate. `workbench_v2/raw_inbox.py` is a synthetic projection, not a Sheet writer or notification service.
- Use the connected Google Drive/Sheets tool for native Sheet metadata, bounded cell reads, formats, data validation, and batch updates. Prefer the native API over an imported XLSX for the operating workbook. Preserve existing `박경찬_DB_*` tables and their SPT consumers until an exact migration is reviewed.

## Review and verification

- Prototype with invented students in an owner-owned workbook. Compare cell design in an actual native Sheet, including frozen rows, row height, width, wraps, contrast, unknown status, and mobile controls. The current three-sample workbook is linked in `review/main_sheet_v3_architecture.md`.
- Use Bun/TypeScript for new engineering and `bun test` with exact test paths for focused checks. The existing `workbench_v2` Python test gate remains scoped to its existing synthetic implementation. Source route and student lookup use `bun run harness roster` and `bun run harness routes`; never search raw dumps for IDs or routes.
- For repeated academy fact requests, run `bun run harness/lead.ts pilot --json`, then `bun run harness/lead.ts plan --fact <fact> --student-id <canonical-id> --date <date> --json`. A blocked plan stays unknown and should lead to the specified safe investigation path before another teacher question. The existing `harness/academy.py read` is the current unique verified DayRecord reader exception: use it only with the exact bounded plan, declared local reader environment, and an explicit ephemeral session. Do not expand Python planning or substitute a shell route or scratch script.
- Prefer the project-local official `chromeDevTools` MCP for bounded, passive teacher-site request-shape inspection after verifying the actual browser, account, tab and route. Use textual snapshots and filtered network tools before screenshots; the Playwright `localBrowser` is a fallback. A configured MCP or saved login is not proof of a current connection. Do not extract a cookie or probe an unknown-effect route. Run `bun run harness/lead.ts coverage --json` to see actual read coverage before promising an app or LMS fact.
- A DayRecord `observed_row` proves only a bounded page observation. Its `occurrenceBinding=unverified` is a hard stop for projecting prior homework or page completion as a confirmed source fact. `--group-id` can check one exact historical group, but an absent row in every current canonical group still does not prove no homework existed.
- Before an academy Sheet batch, refresh metadata and protections, list exact target ranges, before/after values, and recovery method for teacher approval. Read back those same ranges after the approved write. LMS save has its own exact field, target, and readback contract.

Do not copy or install an open-source grid just because it has many stars. Evaluate it against native Sheets editing, mobile behavior, licensing, maintainability, and verified source access. Keep external examples as design references unless they demonstrably improve the operating workbook.
