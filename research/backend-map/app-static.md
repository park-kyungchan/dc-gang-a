## Minimal join spine and data rules

```text
LMS student identity (stu_pri_no; map login_id and app ID explicitly)
  + course/enrollment + lesson date/record keys
  -> preparation submission / video status
  -> DT-ZT and progress
  -> assessment category (ass_no) + paper (p_no) + attempt (testing_no)
  -> item (lecture_key) -> official answer/image/lecture metadata
  -> workbook assignment/attempt, if a key relation is proven
```

The DayRecord parser provides `course_seq`, `stu_pri_no`, `record_seq`, and `cm_seq`, plus report references (`C:/Users/packr/Desktop/강의하는아이들_대치점_자동화/ganga/lms/reader.py:274-298`). It does not itself join app submissions, question attempts, or Smartbook. Preserve distinct IDs, source timestamp, completeness/pagination, and a visible `unknown` state. Do not join by student name. Keep original media as a link in Main Sheet as the owner requested; store text observations/drafts in approved cells, with source and revision metadata. Do not turn local teacher-tool schemas into claims of current academy truth.

## Teacher decisions to ask after field-level inspection

1. Which app facts actually change a lesson decision: assignment, opened, watched, submitted, teacher reviewed, mastered, or needs retry? Define these separately rather than one “complete” flag.
2. For concept videos and handwriting, does the teacher need a thumbnail/link, rubric and feedback state, watch duration, or only a missing/submitted alert? Which actions occur before class versus during clinic?
3. Which paper and Smartbook actions should Main Sheet eventually request or launch, and which remain links to the official UI? A catalog, a created paper, an assigned paper and a scored attempt are different states.
4. Does one student have multiple courses, groups, attempts, or lessons on a date? Confirm the correct selector and history horizon before flattening any view.
5. What freshness and correction history are needed for each app state? Submission, grading, feedback and reattempt can change after a sheet cache is populated.

The first acceptance slice remains the owner-selected 2026-09-21 lesson from preparation to immediately before manual parent delivery. This map enables that slice while retaining the wider student lifecycle as separate, explicitly unverified joins.
