## Current UI friction and Main Sheet implications

1. **Observed:** DayRecord is a date-scoped table with a group selector. The 2026-09-21 unfiltered view had all three rows; filtering also worked. A Main Sheet date then student selector can index those rows without making group mandatory. It should retain group as a secondary filter and show the selected student's row keys only in protected internal data, not in the visible UI.
2. **Source-supported, not freshly exercised:** Progress, homework, memo, and persistent memo are updated by field-specific functions, with blur-style autosave for some inputs (`A/endpoints.py:241-257`; CISM blur save at lines 563-571). The Main Sheet needs visible draft/review/saving/verified/error states and exact-field reread after saving. A cell edit or a 200 response cannot stand for verified LMS persistence.
3. **Observed:** A row's sent icon, the `DailyReport` preview, and the Kakao send popup are distinct artifacts. The preview did not verbatim contain all current DayRecord text. Show separate columns/cards for `LMS current fields`, `LLM draft`, `current report preview`, `LMS sent-labelled state`, and `verified receipt` (unknown until sourced). Preserve timestamp/source for each; do not fill the last two from report URL existence.
4. **Observed/inferred:** The send screen has immediate and reserved-send controls and uses a separate mutating POST. Opening it is a deliberate final human handoff; Main Sheet may link to the correct date and target, but must keep actual send outside automation. As a usability inference, date/student context and a readiness checklist can reduce navigation across schedule, DayRecord, report preview, and popup. A complete student-wide overview across the whole LMS/app has **not** been observed in one existing screen.
5. **Partly verified, with a remaining gap:** The separate Alimtalk history route exists and renders a table. The historical Wiki describes recipient masking, template, send time, reservation, and delivery states, while the bounded live read verified only the route, field names, table shape, and static status-label presence. It did not establish a `report_seq`/message join, exact parent-delivered text, recipient acknowledgement, or an immutable snapshot. Before claiming the requested `sent text versus draft` comparison, identify those read-only fields and their timestamps. Until then, show `LMS report as currently rendered`, the row's UI sent label, and the history-list status as separately sourced states, with receipt/exact sent text marked unknown.
