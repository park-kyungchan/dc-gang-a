## Instructor UX implications

1. A single student/date view needs separate adapters for preparation, course, DT/ZT, and Smartbook. Each displayed state must include its source, refresh time, and explicit `unknown` or `not loaded` value where the source does not prove coverage.
2. Existing site filters differ by screen: date range in preparation, `sort_date` in results, grade/class/student/course in progress, and a multi-step date/class/student/workbook selector in Smartbook. The Main Sheet can normalize the user selection while retaining each source's actual key and freshness. Do not assume one date or student key works across all routes.
3. Distinguish catalog/assigned/attempted/graded/teacher-reviewed states. Workbook catalog and result routes are separate; the current pass did not prove a selected student's assignment or completion.
4. Keep official site links for actions such as progress updates, course-status changes, grading, item opening, paper creation, and app media playback until each exact operation is classified. The selected 2026-09-21 first acceptance slice can show source-backed readiness and explicit gaps before the instructor's manual parent send.
